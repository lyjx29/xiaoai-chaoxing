## 官方接口核对

| 服务 | 官方文档 | 结论与调整 |
| --- | --- | --- |
| DeepSeek | [入门](https://api-docs.deepseek.com/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Anthropic 兼容](https://api-docs.deepseek.com/guides/anthropic_api/) | Chat Completions 仍可用；当前默认名 deepseek-flash。旧 deepseek-v4-flash 仍接受，由当前 Flash 模型提供服务。默认思考开启，旧 1500 Token 预算可能只产生思考内容；新增开关，默认显式关闭思考，新安装输出上限 4096。已保存配置保持不变。 |
| Anthropic | [Messages](https://platform.claude.com/docs/en/api/messages/create) | 原生地址为 /v1/messages；根地址、/v1 和完整路径均可填写。读取全部 text 块，跳过 thinking 等非文本内容，不再只读取首块。仍使用兼容版本头 2023-06-01，未盲目迁移到新的 API 版本。 |
| OpenAI | [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) | Chat Completions 仍存在。官方端点使用 max_completion_tokens；识别 o 系及 GPT-5/6 等模型名称时省略自定义温度，避免旧参数导致错误。第三方 OpenAI 兼容端点可使用 Claude 名称，不再因此误切换 Messages 协议。 |
| Ollama | [OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility) | 本地 /v1/chat/completions 不要求 Key；localhost/127.0.0.1/IPv6 回环可以留空。远程服务仍要求 Key。 |
| ScriptCat | [API 文档](https://docs.scriptcat.org/docs/dev/api/) | 继续使用兼容的 GM 存储和请求 API；敏感设置只写 GM，不再双写网页 localStorage；旧值读取迁移后删除网页副本。 |

未携带密钥，对 DeepSeek、Anthropic、OpenAI、Moonshot 的现有 Chat/Messages 地址发出空 JSON POST，均收到 HTTP 401。Anthropic、OpenAI、Moonshot 返回缺少或错误 Key 的 JSON；DeepSeek 返回非 JSON 的 401。这仅说明本环境能到达相关地址并收到鉴权拒绝，不能证明余额、模型授权、真实请求参数或 AI 作答已验证。

## 开源项目交叉参考

只参考可观察的接口约定与页面结构，改动为本项目独立实现，未引入第三方题库、网页 AI 桥接或新的挂机能力。

- [yxxawa/xuexitong-ai-helper](https://github.com/yxxawa/xuexitong-ai-helper/tree/e6888569568d67a9907dfc9548ebcd56cc2dfa3b)：查看 `utils/ai.ts`、`utils/cx-question.ts`、`utils/question-guard.ts`、`projects/cx.ts`。确认协议应按地址判断，数字题型字段须与内部枚举分开，并优先使用带题号的 type/answertype 字段；平台 typeFlag 不代表题型。
- [ocsjs/ocsjs](https://github.com/ocsjs/ocsjs/tree/91bf7611a281fdeb6937e70d9cc49759a805de1e)：查看 `projects/cx.ts`，对照 .questionLi/.TiMu、.answerBg .answer_p、input[id^=answertype] 等页面结构。
- [Z-Fovik-RT/chaoxing-ai](https://github.com/Z-Fovik-RT/chaoxing-ai/tree/3c152e4a69fe5b27a8211a6472adcca0b1c729ca)：查看其 userscript 声明、自定义 Provider 与请求方式，确认用户自定义域名需要跨域访问能力。新版使用 @connect *，由脚本管理器处理域名授权。

平台数字题型的 17 映射到内部编程题 9；11 等尚未实现题型明确跳过，避免误猜为简答题。新增选择器同时用于读取和点击，保留原有 DOM 探针键，以免已有诊断工具失效。

## 修复与验证

- 正式构建默认 DEV_MODE=false；原基线为 true。原“关闭开发模式”测试可能因导出失败返回 null 而误通过，新增测试直接断言不会写开发日志。
- 网络重试最多 2 次（总计 3 次），仅用于超时、网络故障、429 与 5xx。使用退避和 Retry-After（单次最多 60 秒）；401/403 与同步权限拒绝直接报错。看门狗会中止旧请求，忽略旧请求迟到回调。
- AI 最终答案为空、仅思考或输出截断时不当作成功答案。
- API 连接结果显示使用文本转义，版本标签只接受稳定三段式版本号，更新失败也限频。
- 版本号统一从 package.json 读取；修复 GitHub Actions 的标签触发、发布写权限、PR 检查和 npm ci 安装。
- 测试结果：Node.js 20 下 65 项核心测试、27 项 DOM 测试、36 项维护回归测试全部通过，共 128 项。此前同一维护主体在 Node.js 22 下也通过；最终补充的地址测试以 Node.js 20 为准。
- 验证命令：`npm ci --no-audit --no-fund`、`npm test`、`git diff --check`。

## 尚未验证
